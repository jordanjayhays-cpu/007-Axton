Loop Engineering — How Niah Runs Itself

The shift: You stop being the person who writes prompts. Instead, you design systems that prompt themselves. Hermes runs Niah's operations in loops — you define the end goal, the agent figures out the steps. Based on the Loop Engineering concept from Hermes + Claude integration research.

The 5-Step Loop

1
Check State
→
2
Decide Action
→
3
Act
→
4
Gather Feedback
→
5
Done?
↯ Deterministic Loop
Clear end goal: tests pass, code compiles, booking confirmed. Niah uses this for: new lead → email sent → follow-up scheduled → done. No judgment calls needed.
↯ Non-Deterministic Loop
Judgment calls: UI quality, outreach tone, event strategy. Niah uses this for: reviewing which events to prioritize, deciding outreach messaging, evaluating lead quality.

6 Things That Make Loops Work

Context Management
What goes into context each turn — can't rely on chat history alone
Feedback Quality
Test results, screenshots, open rates — what tells the agent how it did
Verification Gates
Checkpoints that say "this task is actually done"
Termination Condition
Rule that tells the loop when to stop — must be explicit
Error Handling
What to do when a tool call fails — spell it out
State Across Turns
External files track progress so context never loses the thread
